# Testing Your Code

Source: https://www.hiredintech.com/algorithms/algorithm-design-canvas/testing-your-code/

Once your code is written, you don't just lift your pen, say "I'm ready" and leave. A great next step is to verify it with several small test cases.

## Why writing tests?

Showing that you know and care about testing is a great advantage. It demonstrates that you understand the important part testing plays in software development. It gives the interviewer confidence that you're going to write unit tests, review your code, and work through example scenarios.

## Sample tests vs Extensive tests

There are two kinds of testing at an interview:

### Extensive testing - what makes a good test case:

- **Edge cases**: Design cases that test min/max values of constraints. Negative numbers, empty arrays, empty strings, etc.
- **Cases where there's no solution**: Make sure the code does the right thing.
- **Non-trivial functional tests**: Test the internal logic of the solution.
- **Randomized tests**: Make sure code works in the "average" case.
- **Load testing**: Test with maximum data allowed by constraints.

### Sample tests - small tests you run at the interview:

Best combination: non-trivial functional + edge + no solution. This gives the highest certainty for the time invested.

## How to prepare

1. Understand the fundamental kinds of algorithm tests.
2. Pay attention to sample test cases for given problems.
3. Always fill in the "Test cases" section of the Algorithm Design Canvas.

# 测试代码

来源：https://www.hiredintech.com/algorithms/algorithm-design-canvas/testing-your-code/

代码写完后，你不能只是放下笔说"我完成了"就走。一个很好的下一步是用几个小测试用例来验证它。

## 为什么要写测试？

展示你了解并重视测试是一个很大的优势。它表明你理解测试在软件开发过程中的重要作用。它让面试官相信你会编写单元测试、审查代码并处理示例场景。

## 示例测试与全面测试

面试中有两种测试：

### 全面测试——什么是好的测试用例：

- **边界情况**：设计测试约束最小/最大值的用例。负数、空数组、空字符串等。
- **无解情况**：确保代码做正确的事情。
- **非平凡功能测试**：测试解决方案的内部逻辑。
- **随机测试**：确保代码在"平均"情况下工作正常。
- **负载测试**：用约束允许的最大数据量测试。

### 示例测试——面试中运行的小测试：

最佳组合：非平凡功能测试 + 边界情况 + 无解情况。这在投入的时间内提供最高的确定性。

## 如何准备

1. 理解算法测试的基本类型。
2. 注意给定问题的示例测试用例。
3. 始终填写算法设计画布的"测试用例"部分。
